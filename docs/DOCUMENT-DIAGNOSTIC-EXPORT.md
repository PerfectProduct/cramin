# Экспорт выбранного документа для диагностики

Документ READY → меню ⋮ → «Сведения и диагностика» → «Экспорт для диагностики».
После предупреждения о содержимом нажмите «Сохранить» и выберите место для ZIP в системном диалоге.
Отмена не читает данные документа. Ошибка сохранения видна в «Сведениях»; приложение пытается
удалить неполный файл. Если провайдер не разрешил удаление, удалите оставшийся ZIP вручную.
Это read-only диагностика, не резервная копия и не команда повторной обработки.

## Формат 1

Все текстовые файлы — UTF-8. В ZIP только фиксированные относительные имена:

- `manifest.json`: `format=cramin-document-diagnostics`, `formatVersion=1`, время экспорта,
  applicationId/versionName/versionCode **экспортирующего** приложения, версия схемы Room,
  documentId, количества строк, `missingData`, правила редактирования ссылок и таблица `files`.
  Для каждого другого файла указаны SHA-256, размер в байтах, `redacted`. Manifest не хеширует сам себя.
- `data/Document.json`: объект выбранного Document, включая языки, pipelineVersion,
  сохранённые snapshots/brief/failure, параметры и счётчики. `sourceRef` очищен от user-info,
  query и fragment; для не-HTTP источника reference пуст. Полный signed URL не сохраняется.
- `data/Sentence.json`, `Segment.json`, `Job.json`, `Card.json`, `Sense.json`, `Occurrence.json`,
  `ReprocessState.json`: массивы соответствующих строк. ID, индексы, диапазоны и связи сохраняются.
  Отсутствующие строки — пустые массивы с отметкой в manifest.
- `snapshots/processing.json`, `topic.json`, `brief.json`: существующие сохранённые JSON-строки
  modelsSnapshotJson/topicSnapshotJson/briefJson отдельными файлами, без заполнения текущими настройками.
- `files/source.txt`, `input.txt`, `text-provenance.json`, `status-snapshot.json`: только существующие
  файлы выбранного документа. Отсутствие каждого явно отражено в `missingData`; файлы не создаются.

`Job.responseJson` сохраняется строкой или null. Для восстановления карточек нужны его EXTRACT и
CONSOLIDATE записи вместе с Sentence/Segment/Card/Sense/Occurrence. EXTRACT содержит сохранённые
разобранные единицы до UnitValidator, иногда объединённые из length-подчастей; это не журнал всех
HTTP-попыток и не гарантированная дословная копия исходного ответа провайдера. Null ответы явно отмечены.
Сохранённые промежуточные/завершённые части консолидации экспортируются как есть внутри responseJson.

Совпадающие с исходным source URL ссылки очищаются также внутри текста/JSON. Если это меняет файл,
`redacted=true`; хеш manifest относится к **экспортированным** байтам. При таком редактировании
provenance.sourceHash исходного source.txt может отличаться от хеша экспортированной копии.
В отсутствие редактирования JSON responseJson и исходные текстовые файлы сохраняются без переформатирования.

Экспорт не включает SecretStore, DataStore, API-ключи приложения, полную БД, другие документы,
общие/документные StudySession, PDF/аудио и произвольные файлы каталога. Архив содержит личный текст
выбранного документа и ответы модели: передавайте его только согласованному получателю.
Содержимое самих пользовательских текстов не является SecretStore и может быть конфиденциальным.

Снимок снимается в транзакции Room под documentLock, только для READY. Запись ZIP в выбранный URI
выполняется после освобождения транзакции/блокировки. Никаких Worker/API/requeue/изменений прогресса нет.
