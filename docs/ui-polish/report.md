# Cramin 0.1.37 — ограниченный проход после принятия 0.1.36

База: `1f99b49f69818d89a4c49bbb1e00e16a74cc5171`, ветка `feat/v1`, исходное дерево чистое.
UI 0.1.36 принят владельцем за исключением перечисленных замечаний. Эта сборка
предназначена сначала для просмотра архитектором; принятие 0.1.37 не заявляется.

## Изменения

| Область | Изменение | Что сохранено |
|---|---|---|
| Пример занятия | Нейтральный HorizontalDivider, по 12 dp сверху и снизу; только между двумя непустыми текстами | Порядок, точные диапазоны подсветки, типографика/контраст, прокрутка, переворот и обработчики |
| Меню документа | Только прежние четыре действия | Единственный вход в сведения, подтверждения удаления/reprocess |
| Сведения | Группа «Расходы и модели»: сумма, оговорка о неполноте, списки моделей | nullable стоимость и расчёт без изменений |
| Чтение | Явная загрузка, данные, настоящий пустой результат, ошибка с повтором | Режимы, ссылки/подсветка, исходный текст без ожидания перевода |
| Подготовка | «Нет карточек по выбранным фильтрам» при существующих карточках | Логика фильтрации; отдельный текст действительно пустой колоды |

Модели запросов берутся из сохранённых Job с `attempts > 0`, а не из текущих
глобальных настроек. Список моделей snapshot подписан отдельно как сохранённые
параметры обработки. Он не выдаётся за историю выполненных запросов. Это доступные
записи БД, не обещание полного аудита всех исторических попыток. Неизвестная стоимость
остаётся неизвестной; распределения расходов по моделям нет. Для длинных ID доступна
полная ширина, переносы и прокрутка.

Не менялись pipeline, классификационная модель/промпт, схема БД, ключи настроек,
StudySessionMachine, StudyViewModel, Undo/resume, TTS и автопоказ. Принятые библиотека,
импорт, настройки и структура экранов не перерабатывались. Платных API-вызовов,
новой генерации материалов, push и публикаций не было.

## Подтверждённая причина ложного пустого состояния

Раньше `DocumentViewModel.paragraphs` использовал
`combine(sentences, segments, occurrences).stateIn(..., emptyList())`.
При первом открытии `TextTab` сразу получал начальный пустой список и показывал
«Текст появится после обработки». `combine` не выдавал собранный текст до первой
выдачи всех трёх запросов, даже если предложения уже были доступны.

Теперь отсутствие первой выдачи (`null`) отделено от полученного пустого списка.
Предложения определяют наличие оригинала; переводы и диапазоны подсветки могут
присоединяться позже. Обновления документа не сбрасывают поток текста. При ошибке
отдельного запроса его ранее полученные данные остаются, показывается ошибка без
сырого исключения и доступен повтор. Данные/подписка живут в ViewModel конкретного
ID после первого посещения (`SharingStarted.Lazily`). Раньше подписки возобновлялись
после отсутствия наблюдателя более пяти секунд; теперь переключение вкладок их
не пересоздаёт. SaveableStateProvider использует ID документа и вкладку; UI при
смене ID также имеет отдельный Compose key.

`buildParagraphs` раньше выполнялся на главном потоке через контекст viewModelScope;
теперь преобразование работает на Dispatchers.Default. Сам текст по-прежнему
рисуется LazyColumn по видимым абзацам. Масштабной переработки БД/pipeline нет.
Точная длительность двух секунд на телефоне не профилировалась: доказана причина
ложного сообщения, а не конкретное распределение задержки по запросам и разметке.

## Целевые проверки

- JVM: ReadingStateTest (3), SelectionRegressionTest (2), SettingsStoreTest (2) — 7 passed.
  Управляемая задержка первой выдачи на виртуальные 2 секунды, независимый перевод,
  истинный пустой результат, исключение/сохранение уже полученного оригинала,
  cancellation, единственная подписка после возврата через 6 секунд, новый документ.
- Android AcceptedUiPolishTest: меню и расходы, неизвестная стоимость без $0,
  возврат «Учить → Читать» с сохранённой позицией; управляемая первая выдача,
  оригинал до перевода, пустой результат, ошибка, смена документа; короткие/длинные
  примеры, прокрутка, Hebrew, отсутствие разделителя без перевода; настоящий
  экран занятия с доступными компактными Undo/play и переворотом.
- Существующие UiFlowsTest: studySessionFlipSwipeUndoAndRoundEnd и
  autoplayPausesOnCancelledPointerAndPauseButtonDoesNotRestart — 2 passed.
- Обычный экран 1080×2400, density 420 (~412 dp), 100%; узкий 840×1920 (~320 dp),
  200%; светлая и тёмная темы. Тестовые модели/тексты существуют только в androidTest.
- Переход чтения подтверждён тестом, а не только кадрами: до освобождения
  MutableSharedFlow проверяются загрузка и отсутствие пустого сообщения;
  затем выдаётся оригинал и отдельно перевод. Продакшен не содержит таймеров.
- Сборка и lint прошли. Lint: 0 ошибок, 18 прежних предупреждений, без suppression:
  GradleDependency 6, NewerVersionAvailable 3 (версии зависимостей вне этого прохода),
  TrustAllX509TrustManager 3 (код зависимости BouncyCastle), UseKtx 3,
  OldTargetApi 1, UnusedAttribute 1, ObsoleteSdkInt 1 (прежние места).
  Имеющиеся предупреждения Kotlin о старом Compose test rule и safe call не скрывались.

Полный набор не запускался многократно. Повторялись только затронутые UI-тесты:
первый захват опережал вывод SurfaceFlinger; ожидание 350 ms добавлено исключительно
в функцию снимка теста. Отдельный исправленный тестовый пример получил точные
диапазоны подсветки. Сборка теста с недоступным syncInputTransactions была исправлена
удалением этого вызова; он никогда не входил в приложение.

## Визуальные материалы и ограничения

`contact-main.png` — телефон владельца / исправленный пример, меню, сведения,
ожидание чтения / результат. `contact-100.png`, `contact-200.png` — варианты тем,
длины, RTL и переносы моделей. `contact-reading.png` — пять состояний чтения.
Оригиналы лежат в `originals/before` и `originals/after`, без ретуши.
В контактных листах изображения только уменьшены и подписаны.

Меню/сведения и основной пример сняты с production-экранов на синтетической БД.
Изолированные длинные/RTL-примеры используют production FlashCard в тестовом
контейнере; загрузка с задержкой — production TextContent с управляемыми потоками.
Это позволяет воспроизводить ожидание/ошибку без вмешательства в настоящую БД.
Отличие окружения от телефона подписано; ширина/плотность и тестовые данные
отличаются от пользовательских. Поведение на физическом телефоне, ручной TalkBack,
озвучивание в наушниках и фоновое воспроизведение в этом проходе не проверялись.

## Обновление и артефакты

Результаты установки поверх 0.1.36, сертификат, SHA-256 и итоговый HEAD см. в
`verification/upgrade-evidence.json`, `verification/signature-037.txt` и `BUILD-INFO.txt`.
Проверка обновления использует только синтетический emulator-5580, не телефон.

Проверка 0.1.36 → 0.1.37 завершена успешно: 7 документов, 6 карточек,
6 смыслов/вхождений, 8 предложений/сегментов и 1 сохранённая сессия совпадают по
всем колонкам. Совпадают и остальные таблицы, включая Room metadata.
Настройки DataStore побайтово одинаковы; категории/NULL, прогресс, избранное,
маски фильтров и настройки не сброшены. Очистка была только перед подготовкой
независимого синтетического сценария, не между установками 0.1.36 и 0.1.37.
В переносимом fixture нет Job-строк: отображение запросов/стоимости отдельно
проверено UI-тестом с Job. Личный ключ владельца не использовался и его Keystore
на телефоне не проверялся. Пакет `pro.perfectproduct.cramin.debug`, versionCode 37.

SHA-256 сертификата совпадает с 0.1.36:
`e2b2c67220e6f499261c38de69587cb2838293b235977a479a6d504025abe529`.
SHA-256 APK: `2cbb062c47d410b435dcd2178db6447f5437b113a28cec3957fc79112261c3b1`.
APK также проверен на отсутствие префиксов локальных секретов и тестовых классов.

Порядок просмотра архитектором: contact-main → contact-reading → contact-100/200.
При необходимости проверить полные PNG из originals. До передачи владельцу
сопоставить основной пример и меню с его исходными фотографиями, затем проверить
тест перехода загрузки в verification/android-100-True.log и ReadingStateTest XML.
