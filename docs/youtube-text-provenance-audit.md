# Проверка происхождения YouTube-текста — 2026-10-04

Объект: сообщение владельца о “What Is RAG and How Does It Work?”, RU → EN,
125 предложений, STT 1/1, 86 карточек / 123 вхождения. Проверены исходники
`feat/v1`, исходный HEAD `2c05649` (30 коммитов, версия 0.1.30-debug), история
с `2fc5d06` и локальный NewPipeExtractor v0.26.5 (байткод установленной зависимости).
Телефон, его БД и source.txt недоступны в этой проверке. APK 0.1.30 из Downloads
доступен для сравнения подписи; установленный на телефоне бинарник не извлекался.
Видео по заголовку не искалось, сеть/платные модели для анализа не использовались.

## Установлено

* С момента появления YouTube в `2fc5d06` STT означает вызов `Transcriber` для
  аудиочасти. Задания создаются только в `DocumentProcessor.transcribeStage`;
  успешный ответ сохраняется в `Job.responseJson` как текст. DONE при повторе
  означает использование уже сохранённого ответа, а не новый HTTP-вызов.
  Получение субтитров STT-заданий не создаёт. Поэтому предоставленное STT 1/1
  свидетельствует об успешном распознавании одной части в истории документа,
  а не об авторском происхождении текста. Историю переобработок и соответствие
  исторического задания текущему source.txt без самих данных доказать нельзя.
* Запрос — POST `/api/v1/audio/transcriptions`, JSON `model`, base64
  `input_audio` формата m4a, `language`. Это запрос транскрибирования, не
  перевода; targetLang, заголовок видео, glossary, prompt и предыдущая часть
  не передаются. Язык: сохранённый sourceLang, иначе подсказка извлекателя;
  при отсутствии языка — YOUTUBE_NO_LANG. RU→EN в интерфейсе само по себе
  не доказывает сохранённый исторический параметр STT-запроса.
* Модель выбирается настройкой роли STT. Текущий дефолт конфигурации —
  `openai/whisper-large-v3-turbo`; это НЕ установленная модель старого документа.
  `Job.model` — доступное историческое свидетельство. После `6fa1b28` настройки
  замораживаются до STT; ранее конфигурация читалась на стадии распознавания.
  Неполный legacy snapshot не восстанавливает отсутствующие параметры запроса.
* NewPipe перечисляет captionTracks и выставляет isAutoGenerated по префиксу
  `a.` у vssId. Cramin отбрасывает эти дорожки. Автосубтитры используются только
  как подсказка языка (если их языки дают один поддерживаемый вариант).
  `NON_AUTO_REPORTED` означает именно сообщение библиотеки, не доказанное
  ручное авторство: загруженный человеком машинный текст не отличим по флагу.
* Язык видео берётся из languageInfo, затем из языка автодорожек. Среди
  неавтоматических дорожек выбиралась одна соответствующая языку, либо первая
  поддерживаемая, если язык неизвестен. Несколько дорожек не склеиваются.
* NewPipe v0.26.5 удаляет `&tlang=...` из baseUrl; Cramin не запрашивает
  автоматический перевод дорожки. Загруженные переводы всё же могут числиться
  неавтоматическими субтитрами. Приложение не знает, кем и как они созданы.
* При отсутствии подходящих субтитров скачивается один M4A-поток. Ранее выбор
  был «первый itag 140, иначе максимальный M4A bitrate», без языка/типа аудио.
  NewPipe предоставляет audioLocale/audioTrackType; они раньше игнорировались.

## Путь оригинала и примеров

В этой реализации нет поля с именем `originalText`. Его роль выполняют
`docs/{id}/source.txt` и `Sentence.text`.

`Extracted.Text` → source.txt; для субтитров перед этим SubtitleCleaner удаляет
таймкоды/теги, объединяет реплики пробелами, схлопывает соседние полностью
одинаковые реплики. Частичные перекрытия rolling captions не схлопываются:
такой вход может дать повторяющиеся слова, но это не установленный вход данного
документа. Исходные файлы VTT/TTML/SRT исторически не сохранялись.

`Extracted.Audio` → AAC-части до 600 секунд через MediaExtractor/MediaMuxer →
STT text для каждой части → объединение `\n\n` → source.txt. Сэмпл записывается
один раз, затем extractor.advance(); намеренного перекрытия частей нет.
При повторе ArrayList создаётся заново: ответы не дописываются к прежнему source.txt.
Сами повторы внутри ответа распознавателя не удаляются. Аудио после успеха
удаляется. Раньше ответ дополнительно trim-ился; теперь его пробелы сохраняются.

Segmenter выполняет NFC/нормализацию пробелов и разбивку предложений, не переводит
слова и не исправляет смысл. source.txt остаётся сохранённым исходным текстом.
TRANSLATE пишет `Segment.translation`, не `Sentence.text`. TextTab SOURCE_ONLY
показывает TextSentence.text. CardRepository строит исходный пример из
OccurrenceRow.sentenceText, перевод — из segmentTranslation. EXTRACT/CONSOLIDATE
выбирают вхождения/значения, но не записывают заново исходные предложения.
Восстановление консолидации из кэша также не переписывает оригинал.

Подмены полей оригинала переводом в проверенных путях не обнаружено.
Хорошо сформулированный английский пример рядом с испорченным русским может быть
результатом перевода испорченного входа; это возможность, не установленная причина.
Текст о «редакторе субтитров» сам по себе не доказывает использование субтитров:
без ответа STT/аудио нельзя отличить входную речь, ошибку модели и иной источник.

## Подтверждённые дефекты и изменения

1. При неизвестном языке выбиралась произвольная неавтоматическая дорожка.
   Теперь нужна известная совпадающая языковая подсказка; auto и явный tlang
   исключаются внутри самого селектора. При неизвестном языке — аудиопуть,
   затем безопасная ошибка выбора языка, если его установить нельзя.
2. Аудио выбиралось без языка и типа, могло оказаться дубляжом. Теперь
   исключены известные DUBBED/DESCRIPTIVE/SECONDARY и несовпадающий язык,
   приоритет у ORIGINAL. Несколько разных неразрешимых trackId не выбираются
   произвольно. Отсутствующие метаданные остаются UNKNOWN, не ORIGINAL.
3. Повторное скачивание аудио могло смешать сохранённую часть старого потока
   с частью другого: кэш проверял только индекс. Теперь DONE-части связаны
   SHA-256 всего аудиофайла, языком, моделью и числом частей. Проверка всех
   DONE выполняется до новых запросов. Несовпадение или старый неподписанный
   таким идентификатором кэш останавливают STT, не оплачивают новый запрос.
   Это консервативно: повторно упакованный, но семантически тот же файл тоже
   может быть отклонён. Уже существующие source.txt/предложения используются
   как раньше, поэтому READY-документ владельца эта проверка не перерабатывает.
4. Происхождение не сохранялось. Добавлен атомарный text-provenance.json,
   привязанный хешем к точным байтам source.txt. Несовпадение, отсутствие или
   повреждение дают UNKNOWN. Для новых YouTube сохраняются фактический путь
   CAPTIONS/AUDIO_STT, язык/тип выбранной дорожки, язык и модель STT. Для
   неавтоматических субтитров тип честно обозначен NON_AUTO_REPORTED.
   «Скопировать диагностику» показывает сведения и отдельно сохранённые
   completed STT parts / модели. URL, ключи, текст, хеш источника не экспортируются.

Ни один из этих дефектов не доказан причиной `cancer` и повторов у владельца.
С одной STT-частью смешение разных частей тем более не объясняет результат само
по себе. Глобальные замены, LLM-исправления оригинала и фильтрация английского
не добавлялись. Карточки, статусы и прогресс владельца не изменялись.

## Что остаётся неизвестным

Точная ссылка/video ID; аудиодорожка и её язык/дубляж; реальные слова аудио;
исторический STT request language и модель (пока нет выгрузки Job.model);
точные исходный ответ STT и source.txt, факт иных переобработок. По одному
заголовку/125 предложениям/счётчикам нельзя локализовать появление `cancer`.
MATCHES_SAVED_PIPELINE_RESULTS и duplicateMeaningCards=0 проверяют структуру
сохранённых результатов; NOT_VERIFIABLE_FROM_CACHE не является оценкой качества
или доказательством корректности распознавания/перевода.

## Минимальный путь к качественному тексту

В текущем интерфейсе нет выбора конкретной дорожки, принудительного STT или
редактора существующего оригинала. «Обработать заново» сохраняет source.txt и
не исправит распознавание; для данного документа эту кнопку использовать не надо.
Повторный импорт ссылки создаёт отдельный документ, но автоматический выбор может
опять взять субтитры, а качество повторного STT не гарантировано.

Доступный безопасный путь: получить проверенный транскрипт нужного видео,
при необходимости исправить его по аудио вне приложения, затем импортировать
через существующее «Текст» отдельным RU→EN документом. Старый документ и его
8 выученных карточек оставить. Создание новых карточек потребует обычных модельных
запросов позже, после отдельного решения владельца; в этой проверке их не было.
Для осмысленного выбора между другим транскриптом и повторным распознаванием
нужны точная ссылка и доступ к оригинальному аудио/дорожкам; для расследования
нужны также новая безопасная диагностика, а при согласии владельца локальные
source.txt и сохранённый ответ STT (не технические логи).

Один следующий шаг владельца: прислать полную ссылку на исходное видео.
