# BRIEF: диагностика 2026-10-03

## Что известно с телефона

PDF, URL и YouTube дают извлечённый текст и `BRIEFING / BAD_REQUEST`. Вставленный текст
после похожего отказа обработался повторно. Это не доказательство общего дефекта источников,
превышения контекста или исправления исходных отказов.

В 0.1.23 `failureJson` содержит только `source`, `stage`, `code`; fallback из `errorCode`
даёт UNKNOWN stage. Переданное BRIEFING соответствует сохранённому событию, а не вычислению
по progress. `Cramin 0.1.23-debug` и `Android API: 34` подставлены **при копировании**.
Ни момент отказа, ни его версия, запрос и HTTP-статус не сохранены в этой диагностике.
Сам телефон/БД не читались; вывод основан на коде установленной версии и переданных блоках.
Существование snapshot не доказывает, что именно он использовался для последнего отказа.

## Запрос до исправления

| Поле | Новый snapshot | Legacy roles-only |
|---|---|---|
| model | сохранённая роль | сохранённая роль |
| max_tokens | сохранённое значение (6000 в embedded BRIEF) | сохранённое значение |
| temperature | только если поддержан сохранённым каталогом | отправлялся без проверки capabilities |
| reasoning | сохранённый JSON, фильтр поддержки | сохранённый JSON без фильтра |
| system/schema | текущая версия приложения | текущая версия приложения |
| input words | сохранённый pipeline cap | default pipeline cap, исторический неизвестен |
| response_format | strict json_schema document_brief | то же |
| provider | require_parameters=true; без order/only | то же |

Embedded: `openai/gpt-5.6-luna`, 0.2, max_tokens=6000, reasoning.effort=none, 60000 слов.
Это **не установленные параметры телефона**. Публичный каталог на дату проверки сообщает для
этой модели context=1050000, output=128000 и не перечисляет temperature. Безопасная бесплатная
проверка каталога сохранена отдельно. Каталог не подтверждает доступность конкретного маршрута
аккаунта или допустимость каждого reasoning.effort. Поле require_parameters ограничивает роутинг;
account/provider preferences не известны. Неподдержанный temperature может исключать маршруты.

## Подтверждённые локальные дефекты и исправления

- При cap < 20000 head игнорировал меньший лимит. Теперь учитывает min(head, cap).
- Один абзац длиннее cap мог давать пустую выборку. Теперь используется ограниченный префикс.
- BRIEF не резервировал полный prompt/schema/output относительно context. Теперь используется
  единый transport serializer, UTF-8 bytes proxy + output + 1024; короткий текст не меняется,
  длинный сокращается по границе без разделения surrogate pair. Не точная токенизация.
- Legacy frozen snapshot с отсутствующим каталогом обходил фильтрацию параметров. Теперь
  дополняет только отсутствующие capabilities тех же моделей, сохраняет перед запросом;
  неизвестные legacy capabilities дают локальный отказ, без платного угадывания.
- Разные HTTP 4xx и ошибки внутри HTTP 200 сливались в BAD_REQUEST без причины. Теперь точные
  машинные коды различают context/output/token/payload, parameter/schema, model/route и unknown.
  HTTP 404 означает категорию model/route, а не доказанную недоступность именно модели.

До исправлений wire-тесты падали: 3 sampling/rejection, 1 legacy; отдельный запуск 2 legacy/volume.
HTTP сериализация тестируется через MockWebServer и настоящий DocumentProcessor/Room, не только
через вспомогательную модель. Эти искусственные ответы не воспроизводят три исходных отказа.
60000 русских слов × прежняя эвристика 2.6 = 156000 приблизительных токенов текста, без prompt/schema.
Это не доказательство переполнения контекста в 1050000. Реальное число зависит от tokenizer и текста.

## Новое безопасное событие

Снимок создаётся из реально сериализованного body на каждой HTTP-попытке. Отказ сохраняется
callback в `failureJson` перед transport retry / раскруткой исключения Worker. Сохраняются:

- локальный случайный attemptId, время начала/ответа, build version/code, NEW_SNAPSHOT /
  LEGACY_FALLBACK / UNKNOWN;
- requestedModel отдельно от responseModel; провайдер только из сообщённых полей и allowlist;
- HTTP отдельно от API status, X-Request-Id UUID или generation ID установленного формата;
- длины system/user в UTF-16 units, UTF-8 bytes текста и полного JSON; оценка input tokens =
  serialized bytes, явно `...PROXY_V1_NOT_TOKENIZER`; протокольный запас BRIEF дополнительно 1024;
- отправленные max_tokens/temperature, allowlisted reasoning (effort, max_tokens, enabled,
  exclude), состояние COMPLETE/PARTIAL_ALLOWLIST/NOT_SENT;
- strict JSON-schema mode, SHA-256 схемы, require_parameters;
- enum причины, только известные имена параметров, неотрицательные числовые metadata limits
  (`limit`, `max_tokens`, `max_context_length`, `context_length`, `max_completion_tokens`).

Отсутствующее — UNKNOWN; опции, которых нет в payload, — NOT_SENT. Из прозы поля не извлекаются. Если metadata.raw содержит JSON (строка до 32768 символов
или объект), читаются только точные code/type, allowlisted param и числовые лимиты;
сырой JSON и message не сохраняются.
Response model записывается лишь при совпадении с requested model; неожиданный alias остаётся UNKNOWN.
Неизвестный provider, нестандартный ID или неподдержанный формат лимита останется неизвестным.
Полный payload, тексты, URL, ключи, raw/error.message и настройки аккаунта не сохраняются.
Старое событие читается без миграции Room; retry не стирает его. Это последнее наблюдавшееся
событие отказа, не журнал всех попыток. При смерти до записи ответа причина может отсутствовать.

## Первичные контракты

- [OpenRouter structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs):
  strict JSON schema и поддержка маршрута. Подтверждённого дефекта нашей схемы не найдено.
- [Provider selection](https://openrouter.ai/docs/guides/routing/provider-selection):
  require_parameters и max_tokens влияют на выбор допустимых endpoint.
- [Parameters](https://openrouter.ai/docs/api_reference/parameters) и
  [reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens):
  max_tokens включает reasoning и видимый ответ, поддержку effort нельзя вывести из одного имени параметра.
- [Errors](https://openrouter.ai/docs/api_reference/errors-and-debugging):
  error.metadata.error_type, optional provider_code, ошибки внутри HTTP 200. Если API сообщает
  только текст, точной безопасной машинной причины у приложения может не быть.

## Первоначальный план платной проверки (выполнен после отдельного разрешения ниже)

Нужны новая safe event после отдельно согласованной попытки, её время/действие (retry либо новая
обработка), факт смены модели/настроек, длина и язык документа. Для исходного воспроизведения —
PDF/характеристики и публичные URL при возможности. Старые три блока конкретную причину не дают.
Не просим ключи, личные тексты, полные запросы и provider bodies.

Предлагаемый бюджет на отдельное согласование: до $0.10 всего, максимум 2 BRIEF-вызова,
без STT/остальных стадий и без auto retry. Перед каждым сверить публичные цены и верхний предел
input/output с запасом, не вызывать при невозможности уложиться в остаток. Первый — короткий
синтетический RU с тем же сохранённым model/config, strict schema и новой диагностикой. Второй —
только при необходимости: длинный синтетический RU в пределах рассчитанного бюджета, если
короткий успешен; либо один контролируемый вариант конкретного параметра, только если первый
отказ назвал его. Не менять модель наугад. Успех synthetic не доказывает успех документов владельца.

HTTP inference-запроса, без клиентских повторов/redirects, STT и остальных стадий. Тест использовал

reasoning.effort=none, JSON_SCHEMA_STRICT, require_parameters=true, одна и та же schema SHA-256.
