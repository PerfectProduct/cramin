# Тематические категории Cramin

Работа на `feat/v1`, исходный HEAD `4fee826590a1585530676f7cca79fbbd5377a3d8`, исходный APK `0.1.32-debug`. Перед работой дерево было чистым. Публикаций, push, merge, release и реальных платных запросов не было.

## Архитектура и поведение

- Room 5: nullable `Card.category` (`CORE`, `RELATED`, `GENERAL`), маска выбора `Document.categoryMask` (по умолчанию 7), неизменяемый `topicSnapshotJson` и отдельная ошибка обогащения `topicError`. `NULL` означает отсутствие классификации, не `GENERAL`. Категория не участвует в ключе `(documentId, lemmaKey, meaningKey)`.
- Фильтры категорий независимы, объединяются через ИЛИ; текущий фильтр колоды применяется через И. Маска сохраняется атомарно, включая быстрые последовательные нажатия. Маска 0 даёт пустой набор и «Выберите хотя бы одну категорию». Счётчики всего документа отделены от выбранного количества; на кнопке «Учить» фактический размер выборки.
- При маске 7 видны и старые карточки без категорий. При узкой тематической выборке они не приписываются ни одной категории; экран явно сообщает число неопределённых карточек и неполноту подборки. Старый полный набор остаётся доступен.
- «Определить категории» / «Продолжить определение категорий» явно помечены как обращение к платному API. Используется отдельный режим существующего WorkManager worker под блокировкой документа. BRIEF/TRANSLATE/EXTRACT/CONSOLIDATE не запускаются заново. Обновляется только поле категории; ID, примеры, перевод, статусы, избранное и учебная история сохраняются. Ошибка обогащения не меняет READY. Повторная постановка активной работы подавляется KEEP; кнопка показывает выполнение.
- Новые документы pipeline v2 получают категории до атомарного сохранения карточек и READY. Сначала нормализуются окончательные значения, затем классифицируются все ещё не размеченные значения, включая single-translation и fallback. При повторной обработке категории не восстанавливаются по лемме, кэш классификации и тематический снимок очищаются.
- Для старого offline-восстановления pipeline v1 допустим исторический набор без категорий с последующим явным обогащением. Offline-восстановление нового pipeline v2 требует уже сохранённых результатов категорий; отсутствующий результат не запускает API и не превращается в GENERAL.

## Модель, контекст, схемы, повторение

Роль `topic` закреплена во встроенном `config/models.json`: `google/gemini-3.1-flash-lite`, `reasoning.effort=low`, промпт `topic-category-v1`. Роль видна в настройках; изменение выбранной пользователем модели консолидации не производится. Автоматической замены модели классификации нет. Диагностика документа содержит фактическую модель/версию промпта и число размеченных карточек.

Если модели совпадают, category входит в каждый объект senses строгой схемы консолидации. Остальные окончательные значения классифицируются отдельным запросом. Если модели различаются, существующая консолидация сохраняет свой выбор модели, а все окончательные значения получает классификатор.

Во всех тематических запросах serializer сохраняет `reasoning.effort=low`, `provider.require_parameters=true`, `response_format.type=json_schema`, `strict=true`, точный enum. Нет перехода на JSON mode или свободный текст при несовместимости. Клиент отклоняет refusal даже при наличии content и finish_reason=stop. Классификатор независимо проверяет завершение, точный набор ID, уникальность и enum. Во встроенном пути дополнительно проверяются все ключи лемм и ID вхождений каждого значения.

Для пакетов используется один сохранённый контекст: заголовок, бриф и подтверждённые подтемы. Новый BRIEF явно запрашивает только подкреплённые текстом подтемы. Для старого документа используются сохранённый бриф и имеющиеся подтемы; пустой список не заполняется знаниями модели. При историческом отказе BRIEF вместо выдуманного описания берётся ограниченная выборка сохранённых исходных предложений (до 1500 слов), явно как данные. Отдельного платного пересоздания контекста для старых документов нет.

Пакеты ограничиваются сериализованными байтами полного запроса и ожидаемым ответом; учитываются сохранённые лимиты каталога, при их отсутствии используются консервативные границы 32768/8192 и запас 1024. Это оценка, а не точный токенизатор провайдера. Предварительное разбиение по 32 лексическим группам не заменяет проверку размера. `length` ведёт к сохраняемому разбиению между леммами; неделимая группа завершает операцию явной ошибкой, без выдуманной категории. У консолидации сохранена существующая обработка length и дерево частей, размер ответа теперь рассчитывается по содержимому; явный лимит пользователя сохраняется.

`Job.TOPIC` хранит завершённые части, SHA-256 полного входного элемента, категории и решения о разбиении. Сохранение части и обновление категорий старых карточек транзакционны. Повтор использует только совпадающий вход; завершённые элементы повторно не отправляются. Невалидный ответ повторяется не более одного раза за запуск; транспортные повторы ограничены существующим клиентом. Новая явная попытка пользователя может повторить оставшуюся ошибочную часть. После аварии между получением ответа и его записью повтор запроса возможен.

## Общая колода и сессии

Категории применяются к исходным карточкам **до** группировки дублей. Представитель выбирается из подходящих источников; скрытые источники не попадают в `duplicateIds`. Общая карточка остаётся невыученной, если невыучен хотя бы один подходящий источник.

Новые сессии сохраняют точный набор источников `sourceGroups`, порядок и существующие индивидуальные снимки статусов для Undo. Свайп меняет только выбранные источники, Undo восстанавливает их точные предыдущие статусы. Набор переживает resume, повтор раунда и перемешивание. Категории входят в ключ новой колоды; маска 7 сохраняет старый формат ключа, чтобы прежние сессии оставались доступны. Изменение фильтра не перестраивает уже начатую сессию.

## Что не подтверждено реальной моделью

Реальных платных запросов не было. Offline-проверки подтверждают контракт, сохранение и интерфейс, **не качество тематической разметки Gemini** и не доступность конкретного провайдера OpenRouter. Не проверялись реальные документы владельца, его устройство или фактическое качество STT; транскрипция в этой задаче не менялась.

[quality-cases.json](quality-cases.json): 26 предварительно вручную размеченных значений (английский, русский, иврит), включая многозначность, тематические глаголы/прилагательные, бытовые аналогии и малые подтемы. Разметка допускает обсуждение и не является эталоном, доказанным реальной моделью.

`scripts/check-topic-quality.py` по умолчанию только готовит 12 строгих запросов: исходный порядок, обратный порядок и два изменённых пакета на документ. Для согласованного отдельно платного прогона нужен явный `--execute-paid` и `OPENROUTER_API_KEY` в окружении. Скрипт не читает `.env`, не включён в Gradle, не вводит денежных лимитов. Результаты позволяют сравнить категории с ручной разметкой и между вариантами упаковки.

## Сценарий владельца

1. Установить новый debug APK поверх 0.1.32, **не удаляя приложение**. Это offline; прежние документы, прогресс и избранное сохраняются.
2. Открыть один старый READY-документ → «Карточки». Убедиться, что при всех трёх включённых категориях полный набор доступен. Нажать «Определить категории»: **это платное обращение к OpenRouter** с вашим ключом. При частичной ошибке карточки доступны, «Продолжить…» повторяет только недостающие части.
3. Переключить «Основные», «Связанные», «Общие», проверить «Невыученные»/«Избранные», количество у «Учить» и вариант с выключенными тремя категориями. Эти действия **offline**, без API и без изменения прогресса.
4. По желанию начать обучение, сделать свайп, Undo, выйти и продолжить: возвращается сохранённый набор. Изменение статуса происходит только при обучении, не при фильтрации.
